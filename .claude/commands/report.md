# 活動報告の作成

ユーザーから共有された **事実情報** に基づいて、活動報告（ニュース記事）を作成する。

---

## 最重要ルール

### 事実厳守の原則

- **共有された事実のみ** を記事にする。推測・補足・背景説明を勝手に追加しない
- ユーザーが言及していない情報、期待、展望、意気込みなどを **絶対に捏造しない**
- 「文章として成り立たせる」ための最低限の接続・敬語・挨拶文は許可する

### 許可される追加

```
OK: 「2026年3月1日に設立しました」→「2026年3月1日に株式会社Singホールディングスを設立いたしました。」
OK: 末尾に「引き続きご支援のほどよろしくお願いいたします。」程度の挨拶
OK: 事実を読みやすく段落分けする
```

### 禁止される追加

```
NG: ユーザーが言っていない「今後の展望」「目標」「意気込み」を追加
NG: 「業界をリードする」「革新的な」等の装飾的な形容詞
NG: 言及されていない背景情報や文脈の捏造
NG: 事実にない数字や日付の補完
```

---

## 入力フォーマット

ユーザーから以下が共有される（全て揃わない場合もある）:

1. **画像パス**: 使用する画像ファイル（任意）
2. **テーマ/タイトル**: 報告の主題
3. **事実**: 報告すべき内容（箇条書きやメモ形式）
4. **カテゴリ**: おしらせ / プレスリリース / 採用情報 / イベント（指定がなければ「おしらせ」）

---

## 出力

### Step 1: 下書きの提示

まず Markdown の下書きをユーザーに **テキストとして提示** する。ファイルには書き込まない。

```markdown
---
title: "記事タイトル"
date: "YYYY-MM-DD"
category: "おしらせ"
---

本文...
```

**下書き提示時の確認事項:**
- 「事実と異なる記述はありませんか？」
- 「追加・削除したい内容はありますか？」

### Step 2: 承認後にファイル作成

ユーザーの承認を得てから以下を実行:

1. `content/news/` ディレクトリが存在しなければ作成
2. `content/news/{slug}.md` にMarkdownファイルを作成
   - slug はタイトルから生成（英語・ハイフン区切り、例: `hd-established-2026`）
3. 画像がある場合は適切なパスを本文内に記述
4. `src/app/sitemap.ts` にニュース記事の動的生成を追加（未対応の場合）

### Step 3: デプロイ

- コミット＆プッシュ
- `npx vercel --prod` でデプロイ

---

## 文体ガイドライン

- **敬体**（です・ます調）
- 簡潔で読みやすい文章
- 1段落は2〜3文程度
- 過度な装飾を避け、事実を淡々と伝える
- 企業の公式発表として適切なトーン

---

## Markdown テンプレート

```markdown
---
title: "タイトル"
date: "YYYY-MM-DD"
category: "おしらせ"
---

本文をここに記述。

画像がある場合:
![代替テキスト](/img/news/ファイル名.jpg)

引き続き、ご支援のほどよろしくお願いいたします。
```

---

## 注意事項

- ニュース記事のファイルは `content/news/` に配置（`src/content/` ではない）
- frontmatter の `title`, `date`, `category` は必須
- 画像は `/public/img/news/` に配置し、Markdown内では `/img/news/` で参照
- 記事追加後は `src/app/sitemap.ts` への反映も確認する
