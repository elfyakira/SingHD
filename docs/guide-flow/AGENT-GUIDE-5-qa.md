# QAチェックリスト — 冒険者ガイド

**このドキュメントは、品質チェック工程を担当するエージェントが読むもの。**
**目的: 完成したページを複数の観点から検証し、修正すべき箇所を報告する。**

**シリーズ設定は `AGENT-CONFIG.md` を参照すること。**

---

## このガイドの使い方

1. 実装済みのコンテンツ（Markdownファイル + データ登録）を受け取る
2. **AGENT-CONFIG.md を読み、品質基準・実装チェック項目を確認する**
3. 以下のチェックリストを全て実行する
4. 不合格の項目は「不合格項目一覧」にまとめて報告する
5. **1つでも不合格なら修正を要求する。「まあいいか」は許されない**

---

## チェック1: 品質基準（AGENT-CONFIG参照）

AGENT-CONFIG の品質基準5項目に**全てYes**と言えなければ不合格。

1. 20代前半の読者が、読んだ後に「次に何をすべきか」わかるか？
2. Singの哲学が自然に体現されているか？
3. RPG要素が「装飾」ではなく「体験の骨格」として機能しているか？
4. 「どこの採用サイトにもありそうな一般論」になっていないか？
5. 読者が冒険診断 or エントリーに進みたくなる感情の流れがあるか？

---

## チェック2: コンテンツ品質

### 行動可能性
- [ ] 読んだターゲットが「次に何をすればいいか」わかるか
- [ ] 手順が具体的か（抽象的な「考え方」で終わっていないか）

### 正確性
- [ ] 全ての数値に出典（調査名・発表元・年度）があるか
- [ ] 推測表現（「一般的に」「よく言われる」「〜でしょう」）が含まれていないか
- [ ] 過去の日付を未来形で書いていないか
- [ ] 数字が文脈に埋め込まれているか（「○○%」で終わっていないか）

### ブランドボイス
- [ ] 見出しが語りかけ調になっているか
- [ ] 本文がです/ます体で、堅すぎず・軽すぎない温度感か
- [ ] RPG比喩が自然に溶け込んでいるか（取って付けた感がないか）
- [ ] テンプレ文言（「成長できる環境」「風通しの良い」等）が使われていないか

---

## チェック3: Markdown品質

- [ ] frontmatterが完全か（title, date, category, excerpt, tags, readingTime, image）
- [ ] excerptが120文字以内か（meta description用）
- [ ] 見出し階層が適切か（h2 → h3の順。h1は使わない）
- [ ] リスト・引用・太字が正しく使われているか

---

## チェック4: データ登録

- [ ] `src/content/guide/[slug].md` が配置されているか
- [ ] `guide-data.ts` にカード情報が追加されているか
- [ ] `guide-data.ts` で `available: true` になっているか
- [ ] サムネイル画像が `/public/img/recruit/guide/[slug].png` に存在するか
- [ ] `sitemap.ts` にURLエントリーが追加されているか
- [ ] `ai.txt` にコンテンツ情報が追記されているか
- [ ] `llms.txt` にコンテンツ情報が追記されているか
- [ ] `docs/インデックス登録リクエスト手順書.md` にURLが追記されているか

---

## チェック5: SEO

- [ ] タイトルが「[記事タイトル] | 冒険者ガイド | SING RECRUIT」形式か
- [ ] excerptがmeta descriptionとして適切か（120文字以内、キーワード含む）
- [ ] tagsがSEOキーワードと対応しているか

---

## チェック6: 禁止事項

以下が1つでもあれば不合格。

- [ ] bounceアニメーションが使われていないか
- [ ] 同色の薄いテキスト（`text-white/70`等）がないか
- [ ] グラデーションが使われていないか
- [ ] 装飾的サイドラインがないか
- [ ] 絵文字アイコンがないか
- [ ] テンプレ的なCTA文言（「あなたの挑戦を応援します」等）がないか

---

## チェック7: 型チェック

```bash
npx tsc --noEmit
```

既知のエラー（gray-matter型宣言）以外のエラーがないこと。
