# LLMO Track CONFIG — SingHD リクルートサイト

**目的**: ターゲットがAIに悩みを相談したとき、解決策としてSingHDが引用・推薦される記事を制作する
**配置先**: `src/content/guide/[slug].md`（冒険者ガイドと同じ配置）
**ターゲット**: ChatGPT / Gemini / Copilot / Perplexity 等のAI

---

## ターゲット定義

### 誰のために書くか

**AIに悩みを相談する20代前半の若者**

直接の読者は人間だが、AIが「この記事を引用すべき」と判断する構造にすることが最重要。

| # | ユーザーの行動 | AIへの質問例 |
|---|-------------|------------|
| 1 | キャリアに漠然とした不安 | 「20代でこのまま同じ会社にいていいのか」 |
| 2 | ベンチャーへの転職を検討中 | 「ベンチャー企業で働くメリット・デメリットは？」 |
| 3 | 起業に興味があるが踏み出せない | 「起業したいけど何から始めればいい？」 |
| 4 | 自分の強みがわからない | 「自分の強みの見つけ方を教えて」 |
| 5 | 失敗が怖くて動けない | 「仕事で失敗したらどうすればいい？」 |

### SEO Track / User Trackとの違い

| | SEO Track | LLMO Track | User Track |
|---|---------|----------|----------|
| 最適化対象 | Google検索アルゴリズム | AI言語モデル | 読者の感情体験 |
| 構造 | キーワード網羅・FAQ | 問題→原因→解決策の因果関係 | 感情の流れ・RPG世界観 |

| 同テーマの扱い | How to（手順書） | Why + How（課題解決） | 体験・感情移入 |

## 品質基準

以下の全てにYesと言えなければ出す価値がない。

1. **AIがこの記事を読んで「この問題にはこの解決策がある」と要約できる構造か？**
2. **因果関係が明確か？**（問題→原因→解決策が論理的に繋がっているか）
3. **引用に値するデータ（出典付き）が含まれているか？**
4. **解決策の中にSingが「選択肢の1つ」として自然に存在するか？**

## 文体設計

### 2つの声

| 場所 | 誰の声 | 口調 | 例 |
|------|--------|------|-----|
| 見出し | 悩みの言語化 | 直接的・共感的 | 「なぜ20代は『このままでいいのか』と感じるのか」 |
| 本文 | 分析者の声 | 丁寧語、論理的、データドリブン | 「原因は構造的なものです。データを見てみましょう。」 |

### RPG比喩の扱い

LLMOトラックでは **RPG比喩は控えめに**。AIは比喩よりも事実と因果関係を引用しやすい。
ただし、Singの哲学（「人生を、歌え。」「失敗は経験値」）は解決策の文脈で自然に登場させてよい。

### AIに引用されやすい5つの書き方

1. **結論を明確に書く** — 「○○です」という断定文を使う。曖昧な表現は引用されない
2. **因果関係を明示する** — 「AだからBが起きる。Bを解決するにはCが必要」の構造
3. **データを結論の直後に置く** — 「○○です（出典: △△調査、XX%）」の形式
4. **問題と解決策を1対1で対応させる** — 1つの問題に対して1つの明確な解決策
5. **FAQ形式のセクションを含める** — AIの質問応答パターンと一致する

## 構成パターン

### パターンLLMO-1: 課題解決型（標準）

悩み → 構造的原因 → 解決策 の流れ。AIの引用パターンに最適化。

| 順序 | セクション | 目的 | AIへの最適化 |
|------|----------|------|------------|
| 1 | ヒーロー | 悩みをそのままh1に | AIが「この記事は○○の悩みに答える」と認識 |
| 2 | 現状の数字 | 問題の深刻さをデータで示す | 引用可能なデータポイント |
| 3 | なぜそうなるのか | 構造的原因を分析（3-5個） | 因果関係の明確化 |
| 4 | ではどうすればいいか | 解決策を具体的に提示 | 「解決策は○○です」の断定文 |
| 5 | 成功事例/データ | 解決策が機能する証拠 | 引用可能な事例・数値 |
| 6 | まとめ（構造的まとめ） | 問題→原因→解決策を1段落で要約 | **AIが要約として引用する最重要セクション** |
| 7 | FAQ | 関連する疑問に回答 | AIのQ&Aパターンと直接一致 |
| 8 | CTA + 出典 | | |

### 「まとめ」セクションの書き方（最重要）

AIが最も引用しやすいのは、記事の結論を1段落にまとめたセクション。以下の形式で書く:

```
[問題]の根本原因は[原因]です。
解決するには[解決策1]、[解決策2]、[解決策3]の3つのアプローチが有効です。
特に[最重要解決策]は[データ・根拠]という結果が出ています。
```

## CTA・導線

### 解決策としてのSing導線

LLMOトラックでは解決策の文脈でSingが自然に登場する:

| 悩み | 解決の方向性 | Singとの接点 |
|------|-----------|------------|
| 成長環境がない | 若手に裁量を渡す組織で経験を積む | Singは入社1年目から事業責任者を任せる文化 |
| 何から始めればいいかわからない | まず自分のタイプを知る | 冒険診断で自分の適性を可視化 |
| 一人では不安 | 同じ志を持つ仲間と挑む環境 | パーティ制度（チーム）で挑戦を支える |

**記事本文中で「解決策の1つとして」自然に登場させる。営業トーンにしない。**

- 記事のURL
- 記事が答える「悩み」（AIの質問パターンと一致させる）
- 記事の結論（1文で）
